Адаптер к внешнему скилу `git-commit` (`github/awesome-copilot`). Оригинал —
`.agents/skills/git-commit/SKILL.md`, восстанавливается `pnpm skills:sync`. **Этот файл
самодостаточен:** всё нужное для коммита здесь, оригинал нужен только чтобы свериться с апстримом.
Из него взят формат сообщений, остальное строже: в этом репозитории коммит — часть процесса
реестра, а не только запись в git.

## Сообщение

Conventional commits: `<type>(<scope>): <описание>`, типы `feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`.
**Описание — по-русски**, как во всей истории репозитория: `docs: заполнен хеш FX-022 в реестре`,
`fix: ledger:fill переписывал описание записи вместо графы хеша`. Английский императив из
оригинального скила здесь не применяется — история читается людьми, которые её ведут. До 72
символов в заголовке.

**Трейлер `Co-Authored-By` сохраняем** — он стоит почти во всей истории репозитория, и коммит без
него выбивается из неё. Строка берётся из требований окружения и ставится последней, после пустой
строки.

## Процесс реестра — часть коммита, а не после него

1. **Запись в `docs/CHANGELOG.md` обязательна**: фича → `FT-`, изменение процесса → `CH-`, каждый
   найденный дефект → `FX-` с графой «Чем найдено». Графа `Коммит` у новой записи — литерал
   `pending`.
2. **Следующим коммитом — `pnpm ledger:fill`.** Хеш нельзя знать до коммита, а `--amend` менял бы
   его снова. Правка реестра своей записи не требует.
3. **Не дроби работу на коммиты без нужды.** Правило `LG-API-03`: `pending` законен только пока он
   введён коммитом `HEAD`. Любой промежуточный коммит, не заполняющий хеши, делает записи
   просроченными и роняет прогон. «Один логический коммит на изменение» из оригинального скила
   здесь означает **одно изменение — один коммит**, а не разбивку по типам файлов.

## Запреты

- **Никогда `--no-verify`.** Хук `pre-commit` гоняет ориентацию, `lint-staged` и юниты; упал — чини
  причину. Он же и есть нижняя планка качества (см. «Кто что гоняет» в `CLAUDE.md`).
- **Никогда `--amend`** по уже сданной работе: на хеш ссылается реестр.
- **Не `git add -A` вслепую.** В этом дереве может идти работа параллельного агента — 2026-09-15
  так в индекс попали чужие правки. Смотри `git status` и добавляй пути поимённо.
- Секреты не коммитятся: `.env`, ключи, токены. `SEC-API-10` смотрит рабочее дерево, историю — нет
  (`BL-012`).

## Порядок

```bash
git status --short          # чьи правки в дереве, кроме твоих
git diff --staged           # что реально уйдёт
git add <пути>              # поимённо
git commit -m "<type>: <описание>

Co-Authored-By: ..."
pnpm ledger:fill            # следующим коммитом, если вносилась запись
```
