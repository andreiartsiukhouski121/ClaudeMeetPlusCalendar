## 5. Risks

- **Acceptance window.** `lead` keeps `ADR-0034` proposed this cycle, so T13 runs with T6 applied
  and T7 not. From T5 until T7, five keys describe a layout the code no longer has: `FACT-3589`
  (`ADR-0027:94`), `FACT-3572` (`ADR-0027:48`), `FACT-3386` (`ADR-0018:59`), `FACT-0026` and
  `FACT-0059` (`docs/architecture.md:115`, `:157`). No check reads them against code, so the run stays green; the window is
  recorded in T14's `FT-` row and its `BL-` row, and closed by T7 + T17. Until then no new line
  (T6, T11, T14) may cite them, or T7 turns `AR-API-14` red in files `implementer-api` does not own.
- **The T3 red is resolution-only** (§6): what proves the units is T5 passing them unedited at the
  exact count, and T16 seeing each new case fail for its own rule.
- **The fixture can mask the walk.** Hence the separate steps in T2/T4: a scanner that returns
  nothing for real files must not stay green on the fixture alone, and T16(b) proves the real walk
  on real Windows paths, the path-dependent relative and spec-only branches included.
- **`AR-API-18` runs only inside `pnpm e2e`/`verify`** (design §8 q2): T5 runs it itself rather than
  relying on the hook.
