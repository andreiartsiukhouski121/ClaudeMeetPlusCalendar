## 2. Contract

**Design §3, not restated** — the three routes, the ten error bodies read from the framework's
sources, the evaluation order, the empty upload DTO, the filename rule, the allow-list, the ten-file
refusal, the headers, the page, the Route Handler. This plan adds only where they are enforced: the
**definition of done of task 11**, byte-for-byte at the `api` level.

## 3. Data

Schema, columns, formats, the literal bytes and the `fil-teacher-3-*` ids are design §4; the plan
fixes only where they land. `apps/api/prisma/seed.ts` applies three `*.seed.ts` modules (task 5);
`e2e/fixtures/seed.ts` gains the same two rows plus the seeded meeting id `AUDITED_PAGES` needs,
exported rather than literal in a spec (task 16). Owners are unchanged — `planner` for api,
`organizer` for functional, both at zero files — and nothing calls `Date.now()`.

## 5. Risks

- **The prefix costs ~2 s a call, about five per `pnpm verify`** (row 3) — +10 s on 66 s, with **no
  cheap lever**: ungenerated, lint and the units both fail. A fresh install pays ~21 s more, once.
- **`.husky/pre-commit` gains ~2 s on its ~6 s floor**: it runs `pnpm test` → `pnpm -r test` →
  `apps/api`'s prefixed `test`. That floor is what design §5 spent a paragraph defending against an
  in-process Postgres, and `CLAUDE.md` puts the bypass threshold at ten seconds — so this spends a
  third of the margin and **leaves none for a second addition**. Task 19 records the real number.
- **CI's Docker is argued, not demonstrated** (§8.10), accepted without a pre-proof run. The risk is
  timing: 180 s must cover a cold `docker pull`, `initdb`, the healthcheck, the reset, the seed and
  `nest start`, and Playwright's timeout names none of them. **The first CI run is the measurement.**
- **`docker` is off the shell's PATH** (row 5): `pnpm db:up` fails as "command not found", which looks
  nothing like a database problem. **`participants String[]` met no probe** (§8.4), fallback a `text`
  column holding JSON; **`nest build` with a generated client is unverified** (§8.7). **As designed:**
  the cap is not transactional (§8.14), Next >2 MiB unmeasured.

## 6. Assumptions and deliberate omissions

- **Watch item, for tasks 19 and 20 to count rather than feel:** two cases have landed **after** this
  plan's gate — the authenticated-page scan and `AL-API-20` — both real, both found by the right role.
  **A third is the threshold**: design §7's retirement analysis has twice named what a retired unit was
  covered by and twice had a hole, so at three the thing to repair is that analysis, not this plan.
- **`pnpm-workspace.yaml` is not touched:** the blocked install scripts are a warning and the CLI
  fetches its engine itself (row 2); approving them would rest the data layer on pnpm's lifecycle
  policy, what design §2 refused. The prefix lands on its seven scripts — `lint:fix`, `test:watch`,
  `test:cov`, `test:debug` are local aliases and go without.
- **Three things the design left to planning, decided here and open to being overruled:** task 6 sets
  `reuseExistingServer: false` on the **api** entry — a skipped command means no
  `db push --force-reset`, so a local run can pass against a previous schema and seed, and design §2's
  reset guarantee is untrue without it; task 15 keeps its Nest call inline; the prefix stays on both.
- **Two corrections to the design, reported rather than taken:** `pnpm test:home-dashboard` does
  **not** lose its subject — `HD-UT-10`, `11`, `15`, `16` are `apps/web` units untouched here
  (row 6) — so only `pnpm test:meetings-detail` goes; and design §6's retirement table **misses
  `FACT-3360`**, which its own §7 contradicts, plus `FACT-3111` and the already-false `FACT-3362`.
