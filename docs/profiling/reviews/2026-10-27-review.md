## 6. What the pipeline says about choosing a path

**The one size rule.** `bugfix-pipeline` §4 (`SKILL.md:130-136`) has four criteria:

1. the cause was not found in about 15 minutes;
2. the fix changes a contract, an invariant, or behaviour another feature's cases rely on;
3. security is involved;
4. more than one module, or both applications, is affected.

The threshold is "strict, not a recommendation", and an owner override names every criterion that
holds (`SKILL.md:142-147`, from `CH-033`'s `FX-046` follow-up, `CHANGELOG.md:86`). Every `FX-` row
from 48 onward carries a `Path:` marker held by `LG-API-07` (`SKILL.md:149-156`).

**Where the threshold is reused for features:**

- `docs/process.md:39-42`: "Below `bugfix-pipeline` §4's threshold, a `FEAT` change skips its
  discovery half … no change folder, no team, only a red test, the fix and a ledger entry. Above the
  threshold every row runs."
- `feature-pipeline/SKILL.md:48-51`: "Phases are never reordered or skipped, but they shrink with
  the task … for work below the `bugfix-pipeline` §4 threshold, the whole discovery half is skipped
